## ۱) چه چیزی در کد پیدا شد (همه با اجرای واقعی تأیید شده‌اند)

### ۱.۱ صفحهٔ سلامت، خرابی پیامک را پنهان می‌کرد ✅ اصلاح شد
`app/api/system-health/route.ts` مقدار ثابت می‌داد:

```ts
checks["sms_gateway"] = { status: "ok", detail: "… آماده اتصال است." };   // همیشه ok!
```

و `app/api/system-status/route.ts` هم `smsGateway: true` ثابت بود.
یعنی حتی وقتی پیامک اصلاً پیکربندی نشده بود، پنل ادمین «سبز» نشان می‌داد.
حالا هر دو از `describeSmsConfig()` در `app/lib/sms.ts` وضعیت واقعی را می‌خوانند.

### ۱.۲ سرویس‌هایی در پنل ادمین پیشنهاد می‌شد که در کد وجود نداشتند ✅ اصلاح شد
`app/admin/settings/page.tsx` این گزینه‌ها را داشت:

```
kavenegar | melipayamak | farazsms | ghasedak
```

ولی `sendOtp` فقط `console | iranpayamak | kavenegar | smsir` را می‌شناخت و بقیه به
`throw new Error("Unsupported SMS_PROVIDER.")` می‌رسیدند.
اگر کسی از همان لیست «فراز اس‌ام‌اس» یا «ملی پیامک» را انتخاب و در `.env` گذاشته باشد،
دقیقاً همین خطا را می‌گرفته.

- `farazsms` حالا نام جایگزین `iranpayamak` است (FarazSMS و IranPayamak یک سرویس‌اند: `api.iranpayamak.com`)
- لیست پنل ادمین فقط سرویس‌های پیاده‌سازی‌شده را نشان می‌دهد
- پیام خطای سرویس ناشناخته حالا سرویس‌های معتبر را فهرست می‌کند

### ۱.۳ موفقیتِ کاذب در کاوه‌نگار و SMS.ir ✅ اصلاح شد (مهم)
کد قبلی فقط `response.ok` را چک می‌کرد:

```ts
if (!response.ok) throw new Error("SMS provider failed.");
```

اما این دو سرویس **خطای کاری را با HTTP 200 برمی‌گردانند**:

| سرویس | پاسخ خطا |
|---|---|
| کاوه‌نگار | `{"return":{"status":501,"message":"اعتبار کافی نیست"}}` با HTTP 200 |
| SMS.ir | `{"status":0,"message":"خط نامعتبر است"}` با HTTP 200 |

یعنی API ما `{success:true}` برمی‌گرداند، کاربر «کد تایید ارسال شد» می‌دید،
ولی هیچ پیامکی ارسال نشده بود و هیچ خطایی هم در لاگ ثبت نمی‌شد.
حالا بدنهٔ پاسخ بررسی می‌شود، علت در لاگ چاپ می‌شود و خطا به کاربر برمی‌گردد.

### ۱.۴ پنل «تنظیمات پیامک» ادمین هیچ چیزی ذخیره نمی‌کند ⚠️ (مستند شد)
`handleSave` در `app/admin/settings/page.tsx` فقط `setIsSaved(true)` را صدا می‌زند؛
هیچ درخواستی به سرور نمی‌رود. پر کردن API Key در آن فرم هیچ اثری ندارد.
منبع حقیقت، متغیرهای محیطی سرور است. یک هشدار صریح به همان بخش اضافه شد.

### ۱.۵ حالت console دیگر «موفقیت خاموش» نیست ✅ اصلاح شد
حالت `console` فقط با `SMS_CONSOLE_FALLBACK=true` (یا بیلد development) فعال می‌ماند؛
در غیر این صورت خطای روشن می‌دهد. مسیر `/api/customer/request-otp` هم در پاسخ
فیلد `channel` را برمی‌گرداند تا معلوم باشد کد واقعاً پیامک شده یا فقط در لاگ است.

### ۱.۶ بیلد پروژه روی نصب تمیز شکست می‌خورد ✅ اصلاح شد (ربطی به پیامک نداشت ولی مانع دیپلوی بود)
`@google/model-viewer@4.3.1` وابستگی همتا `three@^0.183.0` دارد و در `package.json` نبود.
`npm run build` روی نصب تمیز با ۴۸ خطای `Can't resolve 'three'` شکست می‌خورد.
`three` به وابستگی‌ها اضافه شد؛ بیلد حالا پاس می‌شود.

## ۲) نکتهٔ مهم دربارهٔ `NODE_ENV` روی Next.js

بررسی عملی روی همین ریپو نشان داد:

- `@next/env` (لودر `.env`) مقدار `process.env.NODE_ENV` را **تنظیم نمی‌کند**؛ فقط از آن
  برای انتخاب فایل `.env.production` استفاده می‌کند.
- اما **باندلر (Turbopack) عبارت `process.env.NODE_ENV` را هنگام build به مقدار ثابت
  جایگزین می‌کند** — حتی با `Reflect.get` یا دسترسی براکتی. در chunk بیلد‌شده
  عیناً `environment:"production"` نوشته شده بود.

نتیجهٔ عملی: در کد سمت سرور نمی‌توان به `NODE_ENV` به‌عنوان نشانهٔ «روی هاست هستم»
تکیه کرد. به همین دلیل فعال‌سازی حالت console صریح (`SMS_CONSOLE_FALLBACK`) شد.

## ۳) تشخیص قطعی روی سرور (یک دستور)

روی SSH هاستینگر:

```bash
cd ~/domains/miniroyal.shop/public_html   # یا هر مسیر نصب برنامه
bash scripts/diagnose-sms.sh
```

اسکریپت ۶ بخش چاپ می‌کند و هیچ چیزی را تغییر نمی‌دهد:

1. **متغیرهای محیطی واقعیِ پروسهٔ در حال اجرا** (از `/proc/<pid>/environ`) — مهم‌ترین بخش؛
   خیلی وقت‌ها `.env` درست است ولی pm2 با محیط قدیمی بالا آمده.
2. فایل‌های `.env` موجود و کلیدهای `SMS_*` آن‌ها (کلید API ماسک می‌شود).
3. قضاوت خودِ کد (`app/lib/sms.ts`) دربارهٔ پیکربندی.
4. تست خروجی پورت ۴۴۳ سرور به `api.iranpayamak.com` / `api.kavenegar.com` / `api.sms.ir`.
5. فراخوانی مسیر واقعی OTP روی `127.0.0.1:3000` و چاپ پاسخ.
6. لاگ‌های pm2 با فیلتر `MiniRoyal SMS|OTP`.

می‌توانید شمارهٔ تست واقعی هم بدهید:

```bash
TEST_PHONE=09121234567 bash scripts/diagnose-sms.sh
```

## ۴) علت‌های محتمل، به ترتیب احتمال

| # | علت | نشانه در خروجی | درمان |
|---|---|---|---|
| ۱ | `SMS_PROVIDER` / `SMS_API_KEY` در محیط پروسه نیست | بخش ۱ اسکریپت: `خالی است` | `.env` را کامل کنید و `pm2 restart miniroyal --update-env` |
| ۲ | مقدار `SMS_PROVIDER` پیاده‌سازی‌نشده (`melipayamak`/`ghasedak`) | `پشتیبانی نمی‌شود` | به `iranpayamak`/`kavenegar`/`smsir` تغییر دهید |
| ۳ | پاسخ خطای کاری با HTTP 200 (اعتبار تمام‌شده، خط نامعتبر، پترن تأییدنشده) | `HTTP 200` ولی `status:0` / `return.status:501` | در پنل سرویس: اعتبار، وضعیت خط و تأیید الگو را بررسی کنید |
| ۴ | `SMS_LINE_NUMBER` یا `SMS_PATTERN_CODE` غایب/غلط | `SMS_LINE_NUMBER تنظیم نشده` | شماره خط دقیق پنل و کد پترن را بگذارید |
| ۵ | خروجی ۴۴۳ سرور به سرویس پیامک بسته است | بخش ۴ اسکریپت: `اتصال برقرار نشد` | فایروال/CSF هاست را بررسی کنید |

## ۵) تنظیمات مرجع

### ایران‌پیامک / فراز (پترن OTP)
```env
SMS_PROVIDER=iranpayamak
SMS_API_KEY=کلید-از-پنل
SMS_LINE_NUMBER=5000123456789
SMS_PATTERN_CODE=کد-الگو
```
الگوی ثبت‌شده در پنل باید یک متغیر `%var1%` داشته باشد؛ کد ما `attributes.var1` را پر می‌کند.

### کاوه‌نگار
```env
SMS_PROVIDER=kavenegar
SMS_API_KEY=کلید-پنل
```

### SMS.ir (ارسال سریع — توصیه‌شده برای OTP)
```env
SMS_PROVIDER=smsir
SMS_API_KEY=کلید-پنل
SMSIR_TEMPLATE_ID=123456
```
قالب باید پارامتری به نام `CODE` داشته باشد. بدون `SMSIR_TEMPLATE_ID`، از مسیر
`/v1/send/` با `SMS_LINE_NUMBER` استفاده می‌شود که روی خطوط تبلیغاتی ممکن است فیلتر شود.

## ۶) تست خودکار (بدون سرور، بدون کلید واقعی)

```bash
node scripts/check-sms.cjs
```

این اسکریپت `app/lib/sms.ts` را با `tsc` خود پروژه کامپایل و اجرا می‌کند و فقط `fetch`
را mock می‌کند؛ ۲۳ سناریو را بررسی می‌کند (مسیر تصمیم‌گیری، URL و بدنهٔ ارسالی هر سرویس،
پاسخ‌های خطا، مقدارهای env با نقل‌قول، و هم‌راستایی `describeSmsConfig` با ارسال واقعی).
